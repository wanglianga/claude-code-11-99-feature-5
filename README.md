# 多语言通知发布与收悉工作台

为住户的**班车、餐点与集中说明会**等安排提供多语言通知的**编写、翻译、审阅、发布、撤回与收悉**闭环。接待员编写面向楼栋或家庭的安排，翻译志愿者按语言编辑译文并审阅，值班负责人批准发布，住户在本地模拟居民入口查看当前有效安排、确认知悉或提交协助请求。

纯浏览器前端：React + TypeScript + IndexedDB + WebWorker，计算与持久化全部在本地完成，**不依赖后端、不调用真实短信服务**（投递由本地模拟适配器以「短信桩」演示）。全部为虚构楼栋、家庭与通知数据。

## 领域规则实现要点

### 区块、版本与引用

- 通知由若干**区块**组成（主题/服务联系人、时间地点、行动说明），区块间引用必须**显式登记**（如「行动说明」引用「时间地点」的发车时刻）。
- 源文每次修订生成**单调递增的新版本并保留历史**（可追溯 09:00→10:00 的历次修改）；译文不会自动跟随，须重新翻译。
- 译文绑定**所基于的源文版本**；审阅结论绑定「本区块源文版本 + 依赖区块源文版本 + 引用关系 + 区块顺序」快照。**审阅是否有效凭版本快照实时判定，不能只凭译文编辑时间判断。**

### 两条审阅路径（都只能发布完整通知）

- **整份审阅（whole）**：一次审阅整份多语言通知。任一区块源文修订、区块换序或引用变化，整份审阅立即失效，**各语言都要重审整份**（局部修改会拖住所有内容）。
- **区块审阅（block）**：以「区块 × 语言」为单位独立审阅。互不影响的区块译文与审阅可**沿用**；被依赖区块改版时，引用方审阅**连带失效**。删除被引用区块时，引用方进入**待修复引用**，发布前必须改指或移除引用，**不能发布残缺指示**。
- 两条路径都要求**所有必需语言 × 全部区块**译文齐备且审阅有效才能发布；**缺译文本不能补成已批准**。发布前同时校验区块组合完整、顺序连续、引用闭合。

### 发布、撤回与收悉口径

- 发布时固定区块版本、顺序、引用与**投递名单快照**；本地模拟适配器为每位在住对象入队一条短信桩，约 1.5 秒后由 Worker 定时清扫标记「送达」（无真实短信）。
- **发布数量 ≠ 实际收悉人数**：收悉须住户逐人确认；工作台按发布版本统计收悉缺口与协助待办。
- 确认知悉绑定**具体发布版本**：通知再发布新版本后，旧确认不会自动算作知悉新内容；同一版本在两个标签页重复确认**仅记一次**（幂等）。
- **撤回后居民才点击的确认会被拒绝并单独留痕**，不计入收悉；撤回前的回复原样保留。
- **家庭迁出后不再进入新发布名单**，但其此前回复保留出处，可按发布版本追溯。

### 工程约束

- 所有写命令在单个 IndexedDB readwrite 事务内「读取→引擎校验→写回」，多标签共享同一库、天然串行；每条命令带 `commandId`，重复提交幂等。
- 角色权限由引擎在事务内再次校验；虚拟时钟驱动业务时间，模拟投递时延用真实时钟，两者互不干扰。

## 本地启动

要求 Node 18+（容器内固定 Node 22）。

```bash
npm install        # 安装依赖
npm run dev        # 开发模式：http://localhost:5173
```

其他命令：

```bash
npm run test       # 领域引擎单元测试（vitest）
npm run build      # TypeScript 严格检查 + 生产构建到 dist/
npm run preview    # 预览生产构建：http://localhost:4173
```

> 若默认 npm 缓存目录无写权限，可指定项目内缓存：`npm install --cache ./.npm-cache`。

## Docker 一键启动

```bash
docker compose up --build
# 打开 http://localhost:8080
```

多阶段构建：Node 构建静态产物，Nginx 托管，无需任何后端服务。

## 演示账号（角色入口）

无需账号密码，页面右上角下拉切换四个入口，权限由引擎在事务内再次校验：

| 角色入口 | 权限 |
| --- | --- |
| 接待员 | 新建通知、修订源文、区块换序/删除、登记与修复引用、切换审阅模式、办理家庭迁出 |
| 翻译志愿者 | 按语言编辑译文、提交整份审阅或区块审阅（含退回、模拟旧审阅晚到） |
| 值班负责人 | 完整预览、发布完整性检查、发布/撤回、查看收悉缺口与协助待办、模拟投递、办理迁出 |
| 住户（居民入口） | 选择住户身份，查看本人有效安排、确认知悉、请求协助 |

任何角色都可推进演示时间、查看规则核对面板与操作回执流。

## 初始演示数据（严格对应题目示例）

两条同构通知，各含**三个区块、三种语言（中/英/越）**，目标为 A 楼：

1. 区块一「服务联系人」——独立区块，不引用其他区块；
2. 区块二「时间地点」——班车发车已从 **09:00 改为 10:00**（v1 含 09:00 保留在版本历史，当前源文为 v2）；
3. 区块三「行动说明」——**引用区块二的发车时刻**。

- `【整份审阅】…`：三语言在 v1 时批准过整份，区块二升 v2 后**整份审阅全部失效**。
- `【区块审阅】…`：区块一三语言审阅**仍有效可沿用**；区块二因本区块升版失效；区块三因依赖的区块二升版而**连带失效**。
- 译文现状：区块二仅中文已对齐 v2，英/越仍停在含 09:00 的 v1，须重译。
- 住户：A 楼 4 人（王芳、王小明、李强、Lisa）、B 楼 2 人（Trần Văn、Nguyễn Thị）。

## 演示脚本（对应题目要求的验证场景）

1. **两路审阅工作与可发布时间对比**
   - 打开「区块审阅」通知 → 翻译志愿者：把区块二英/越译文重译保存（绑定 v2），逐语言重审区块二、区块三；区块一不动。回值班负责人「发布/撤回」可见三语言进度全绿并可发布——**只重审后两块，第一块沿用**。
   - 「重置演示数据」后打开「整份审阅」通知 → 三语言均须补齐译文并各自「批准整份」，缺一语言发布按钮保持禁用；任一区块再修订或换序，三语言整份审阅再次全部失效。
2. **旧审阅晚到**：翻译志愿者点击「模拟旧审阅晚到」（区块审阅按上一版快照、整份审阅按 v1 快照登记）→ 回执出现「晚到…到达即失效」，对应审阅立即为待重审，不能补成已批准。
3. **区块换序**：接待员用「↑ 前移 / ↓ 后移」调整顺序——区块审阅结论不受影响；整份审阅因组合顺序变化而失效。
4. **删除被引用块**：接待员删除区块二 → 区块三出现「待修复引用」红标，发布被拦截（不会发出残缺指示）；在「登记/修复区块引用」中清空或改指引用后缺口解除。
5. **发布与撤回**：值班负责人发布后，「模拟投递」页可见 4 条短信桩由排队变为送达；「收悉缺口与协助」显示投递 4、收悉 0——**发布数量不等于收悉人数**。撤回后切到住户入口点击确认，会被拒绝并在工作台留痕。
6. **住户确认与幂等**：住户入口选择王芳，对发布版「我已知悉」；开两个浏览器标签用同一住户身份对同一版本再点，回执显示重复确认幂等忽略，收悉仅记一条。
7. **新版本须重新确认**：撤回后不改正文再次发布得到 v2，王芳对 v1 的确认不计入 v2 收悉（缺口重新出现），但 v1 回复仍在版本详情中保留。
8. **家庭迁出**：接待员/值班负责人办理「王芳一家」迁出 → 再次发布的名单不再含其成员；其历史回复仍保留出处，迁出住户点击确认被拒。

## 架构与目录

```
src/
  engine/           # 纯函数领域引擎（UI 与 Worker 共用同一口径）
    types.ts        # 领域模型与命令定义
    seed.ts         # 虚构演示数据（三块三语言、09:00→10:00、两路审阅）
    selectors.ts    # 版本/引用/译文/审阅有效性/发布完整性/收悉口径等纯派生
    engine.ts       # 命令处理、失效传播、发布撤回、收悉、模拟投递、幂等、不变量
    format.ts       # 时间格式化
  worker/           # WebWorker：所有写操作在此串行落库
    store.ts        # IndexedDB 单记录事务（读取→校验→写回）
    worker.ts       # 命令分发 + 本地模拟适配器（投递定时结算）
  ui/               # React 工作台
    client.ts       # Worker 客户端 + BroadcastChannel 多标签同步
    common.ts       # 命令/发送类型
    App.tsx         # 角色入口与工作台装配
    receptionist.tsx# 通知列表/新建、源文区块编辑、引用登记修复、换序删除
    translator.tsx  # 逐语言译文编辑、整份/区块审阅、旧审阅晚到
    duty.tsx        # 完整预览、发布撤回、收悉缺口、协助待办、模拟投递、迁出
    resident.tsx    # 本地模拟居民入口
    widgets.tsx     # 通用卡片、徽章、回执流、规则核对
  test/
    engine.test.ts  # 22 个领域引擎测试
```

关键设计：

- **版本快照驱动的审阅有效性**：审阅不存「当前是否有效」的静态结论，而是在每次结构/译文变更后由 `evaluateReview` 依据源文版本、依赖版本、引用签名与顺序签名实时重算，失效不可凭时间自行恢复。
- **发布完整性闸口**：`releaseCheck` 汇总缺译、过期译文、失效审阅、失效引用、顺序缺口，两条审阅路径共用同一闸口，杜绝缺译补成已批准与残缺指示。
- **版本化收悉**：确认绑定 `publicationVersion`，再发布产生新版本，新旧回复分别留存、缺口按版本独立统计。
- **单记录事务状态**：整份状态存于 IndexedDB 单条记录，跨标签并发由 IndexedDB 序列化，杜绝脏写；`commandId` 提供应用层幂等。
- **数据安全**：全部数据仅存于本浏览器 IndexedDB，清除站点数据即可彻底删除；无任何网络请求。
